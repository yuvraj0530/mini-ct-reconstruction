# MINI CT SCAN RECONSTRUCTION USING LINEAR ALGEBRA

## Project Report

### 1. Abstract

Computed Tomography (CT) is an imaging technique that uses multiple projections to reconstruct an internal image. This project presents a simplified 2D CT reconstruction simulator developed using Python and Linear Algebra.

The system generates test images, simulates beam projections, constructs a mathematical beam matrix and reconstructs images using the least-squares method.

It also analyzes matrix rank and nullity, evaluates reconstruction quality, simulates measurement noise and stores scan history using SQLite.

The project provides an interactive interface through Streamlit to demonstrate the mathematical principles involved in CT reconstruction.

### 2. Introduction

Linear Algebra plays an important role in many scientific and engineering applications. One such application is Computed Tomography.

In CT reconstruction, projection measurements are collected from different directions. These measurements are used to estimate the original image.

The mathematical representation of this problem is:

\[
Ax=b
\]

Here, the beam matrix represents the relationship between image pixels and projection measurements.

This project implements a simplified version of this process to understand the relationship between Linear Algebra and image reconstruction.

### 3. Problem Statement

The objective is to develop an educational 2D CT simulation system that demonstrates how an image can be reconstructed from projection measurements using matrix operations and numerical methods.

The system should also analyze the mathematical properties of the resulting linear system and study the effect of measurement noise on reconstruction accuracy.

### 6. Mathematical Background

#### 6.1 Linear System Representation

The reconstruction problem is represented by:

\[
Ax=b
\]

Where:

- \(A\) = Beam matrix
- \(x\) = Unknown image pixel values
- \(b\) = Projection measurements

The objective is to estimate the image vector \(x\) using the available measurements.

#### 6.2 Least-Squares Reconstruction

When an exact solution is unavailable or the system contains more equations than unknowns, the least-squares method can be used.

\[
x^*=\underset{x}{\operatorname{argmin}}\|Ax-b\|_2^2
\]

The project uses NumPy's `numpy.linalg.lstsq()` function to calculate the solution.

#### 6.3 Matrix Rank

Matrix rank represents the number of linearly independent columns or rows of a matrix.

It helps determine the number of independent equations in the system.

#### 6.4 Nullity

Nullity represents the dimension of the null space.

Using the rank-nullity theorem:

\[
\text{Rank}(A)+\text{Nullity}(A)=n
\]

Where \(n\) is the number of columns of matrix \(A\).

#### 6.5 Types of Linear Systems

- Underdetermined: More unknowns than equations.
- Overdetermined: More equations than unknowns.
- Square: Equal numbers of equations and unknowns.

A unique solution is possible when the matrix has full column rank, provided the system is consistent.

### 7. System Design and Implementation

The project is divided into several modules.

#### 7.1 Phantom Generation

The system generates three types of test images:

- Square phantom
- Circle phantom
- Custom phantom

These images act as input objects for the simulation.

#### 7.2 Beam Matrix Generation

The beam matrix is generated by calculating the intersection length of projection paths with individual image pixels.

Each matrix entry represents the contribution of a pixel to a particular measurement.

#### 7.3 Measurement Simulation

Projection measurements are generated through matrix multiplication:

\[
b=Ax
\]

The original image is converted into a vector before the multiplication.

#### 7.4 Image Reconstruction

The image is reconstructed using the least-squares solution.

The resulting vector is reshaped into the original image dimensions.

#### 7.5 Matrix Analysis

The system calculates:

- Matrix rank
- Nullity
- Independent measurements
- System type
- Whether a unique solution is possible

Singular Value Decomposition (SVD) is used for numerical rank and null-space analysis.

#### 7.6 Matrix Operations

The project implements:

- Matrix transpose
- Matrix multiplication
- Determinant calculation
- Matrix inverse
- Matrix properties

#### 7.7 Database Integration

SQLite is used to store scan history.

Each scan record includes image information, dimensions, projection angles, detector count, matrix rank and creation timestamp.

#### 7.8 Scan Queue

A FIFO queue is implemented using Python's `collections.deque`.

It supports enqueue, dequeue, peek, size and clear operations.

#### 7.9 Noise Simulation

Gaussian noise is added to the projection measurements:

\[
b_{\text{noisy}}=b+\epsilon
\]

Where \(\epsilon\) represents random measurement noise.

The reconstruction is then performed using the noisy measurements.

### 8. Reconstruction Quality Analysis

Three metrics are used to evaluate reconstruction quality.

**Mean Squared Error (MSE)**

\[
MSE=\frac{1}{N}\sum_{i=1}^{N}(x_i-\hat{x}_i)^2
\]

**Root Mean Squared Error (RMSE)**

\[
RMSE=\sqrt{MSE}
\]

**Relative Error**

\[
E_r=\frac{\|x-\hat{x}\|_2}{\|x\|_2}
\]

Where \(x\) is the original image and \(\hat{x}\) is the reconstructed image.

### 9. Experimental Results

An experiment was performed using:

- Image size: 16 × 16
- Projection angles: 12
- Detector count: 16
- Phantom: Square

The measurement noise level was varied to study its effect on reconstruction.

#### 9.1 Matrix Analysis Results

For the same configuration:

- Matrix rank: 152
- Nullity: 104
- Independent measurements: 152
- System type: Underdetermined
- Unique solution possible: False

#### 9.2 Observations

1. Matrix rank and nullity remained unchanged when measurement noise increased.
2. Reconstruction error increased with higher noise levels.
3. The 10% noise experiment produced the highest reconstruction error.
4. The measurement comparison graph demonstrated the difference between clean and noisy measurements.

These results show the impact of measurement noise on reconstruction quality.

*Note: These values are observed experimental results from one configuration and random noise realization. They are not universal performance values.*
